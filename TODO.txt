[SOLID] Intangible people no longer block the pathfinder — SHIPPED v2.30.80 (2026-08-04), superseded-in-part by [SOLID2]
------------------------------------------------------------------------
User report: characters blocked paths even when intangible (the downed
guards on the Sector 1 station platform at the game start). Root cause:
CollectBodies treated collision radius +0x72 as the only tangibility
signal, but the engine's movement test (0x637724) actually gates on the

place, all consumers inherit): CollectBodies now mirrors the engine's
full skip list — SOLID-off byte + its ±128-unit z level gate — beside
the existing radius/parked filters. First retest same day surfaced the
hidden-people gap → [SOLID2].
VERIFY: (a) station platform at game start: guards NOT named as

[DIALOG] "Dynamic tokens" 0xEB-0xF0 — RESOLVED v2.30.17 (2026-07-23): they're just character names
------------------------------------------------------------------------
CLOSED, and much simpler than the deferred investigation assumed. The
0xEB-0xF0 mid-string bytes were being decoded as 4-byte "dynamic
tokens" (header + 3 data bytes, spoken as "[item name]"/"[number]"
placeholders) per an FFNx-derived reading — while 0xEA (Cloud) and
0xF1/0xF2 (Vincent/Cid) were ALREADY single-byte name references. Two
independent raw captures with zero counterexamples proved the split
wrong for field dialog:
  - Tifa, 7th Heaven (2026-07-23 log): `57 49 54 48 00 EB 1F B3 E7 E0`
    = "WITH " {Barret} '?' '"' newline newline. The 4-byte reading
    CONSUMED the '?', the closing quote, and a newline as "data" —
    truncating the line AND speaking "[item name]" (player heard
    "item 1") for what is simply Barret's name.
  - Wedge, train graveyard (2026-07-20): "Hey [item name] What about
    our money?" = "Hey, {Barret}..." (the v2.30.6 residual already
    suspected this).
FIX: mid-string 0xEA-0xF2 is now ONE contiguous single-byte
character-name branch (ff7tk eng[] table: CLOUD..CID), live savemap
names respected. token_placeholder() deleted. No variable-bank
investigation needed. If some other text truly embeds a multi-byte
token in this range, its data bytes will now decode as VISIBLE garbage
in the debug log (re-investigate with evidence) instead of silently
eating real text.
STILL OPEN from the old entry: the `08 0A 3E 05 01` byte run (before a
page break, 2026-07-20 log) that decoded as garbage under the
"<=0x5E is ASCII" assumption — unexplained, unrelated to the name
range, needs its own capture if it recurs audibly.

[CONFIG] Auto-create default config file if missing
----------------------------------------------------
If the user places version.dll in the FF7 folder but forgets ffvii_accessibility.cfg,
Config::Load() currently fails silently and the mod runs with all defaults
(which is actually correct behavior). However, there is no config file for the
user to edit to enable/disable features.

Fix: in Config::Load(), after failing to open the file, write a default
ffvii_accessibility.cfg to the same directory with all defaults and a header
comment explaining each option. This gives the user an editable starting point
without requiring them to find documentation.

Implementation note: the DLL knows its own path via GetModuleHandleEx +
GetModuleFileNameA (same pattern used in TTS::Init() to locate Tolk.dll).
